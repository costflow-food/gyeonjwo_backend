# 최신 Notion 01~07 대비 기존 백엔드 차이

2026-10-28. 요구사항 기준은 [프로젝트 분석](PROJECT_BASELINE_2026-10-28.md), 인수 기준은 [AC 목록](ACCEPTANCE_BASELINE_2026-10-28.md)이다. 이번 작업은 분석/문서 저장이며 아래 기능을 구현 완료했다는 보고가 아니다.

## 판정 방법

로컬 `app/main.py`, `services.py`, `worker.py`, `classification.py`, `documents.py`, `pipeline.py`, `llm.py`, `responses.py`, `config.py`, `db/contracts.py`와 기존 구현 기록을 대조했다. 이번에는 테스트를 다시 실행하지 않았다. 기존 165개 통과는 2026-10-26의 구 요구사항·대체 외부 응답 기반 기록이며 새 AC-01~23의 통과율/완료율이 아니다. 실Supabase·Gmail·LLM·Flutter 연동 미검증 상태도 유지한다.

## 1. 핵심 결론

현재 코드는 **구 SQL/RPC에 연결된 동기 단일 메일 분석기**다. 새 기획은 **업무 그룹·현재 견적·제한된 도구를 선택하는 다섯 역할·실제 발송·회신 이벤트 재개·카드/선택 영속화**가 필요하다. 몇 개 응답 필드를 붙이는 것으로 끝나지 않는다.

기존 수신 복구·OIDC/Auth·Decimal·안전한 파일 파싱·숫자/원문 검증·제한된 산식 검사 등은 재사용 후보지만 새 데이터 계약에 다시 연결해 검증해야 한다. 그대로 복사해 최신 MVP 완성으로 표시하면 안 된다.

## 3. 개발 순서 제안

1. **계약 확정:** 최신 08·09도 읽고 DB 담당자와 UUID/논리 테이블/필수 JSONB·소유·RPC·마이그레이션·상태 전이표를 합의한다. 구 DB를 즉시 덮어쓰지 않는다.
2. **기반:** 버전·감사 로그·사용자 변경 멱등성·메일/업무 분리·권한/소유 모델을 구현한다.
3. **접수/사용자 경계:** 새 업무·활성 회신·보관 회신·모호/비업무, 원문·수긍·복원·명시 재개를 구현한다.
4. **현재 근거:** OCR/표/Excel·원문 위치·추출 도구·견적 불변 저장·입력 revision을 구현한다.
5. **메일 흐름:** 후보/RFQ·스타일·설정·승인/자동발송·UNKNOWN·대조·회신 자동 재개를 연결한다.
6. **판단/계산:** 역전 계산·확인 우선순위·현재 수량/제약별 구매안·역제안 회사 정책 도구를 구현한다.
7. **카드/선택/화면:** 원자적 카드 버전 저장·조회·stale/최종 선택·보관·로그/수신율·프론트 계약을 연결한다.
8. **인수:** AC-01~23에 대해 고정 정답 테스트와 실제 계정 통합 증거를 분리해 기록한다. 오류 재현이 수정됐는지 확인한 후 완료를 선언한다.

## 4. 당장 결정하면 안 되는 것

- 모델명·OCR 공급자·팀 가격/분산/세금 정책·승인 기본값·보관 기간을 임의로 확정하지 않는다.
- 사용자와 논의했던 태풍/월별 갱신/시간대 운영을 새 Must라고 가정하지 않는다.
- 최신 논리 설계가 구 SQL19개 RPC와 호환된다고 가정하지 않는다. 같은 ‘13개’라도 서로 다른 모델이다.
- 바탕화면 `gyeonjwo_backend_2026-10-26`은 별도 스냅샷이다. 이번 10-28 문서는 원래 Documents/Codex 작업 폴더에 저장했으며 그 사본을 자동 갱신하지 않았다.
- 새 설계의 자동 발송 기능 요구가 현재 세션의 거래처 메일 발송 권한을 뜻하지 않는다. 이번에는 외부 발송을 실행하지 않았다.

## 5. 재사용 후보

- 사용자 인증·OIDC·자격증명 분리·오류 정제·본문 크기 제한.
- Gmail 전체 history 페이지·커서 만료 복구·watch 갱신·중복/잠금·재시작 복구의 기본 원리.
- 원문과 DB 본문 일치 확인, 첨부 안전 경로/크기/해시, PDF 격리 프로세스·기술 재시도.
- Decimal·숫자 쉼표/단위 검증·비용 포함/중복 방지·제한된 산식·금액 응답 일관성의 계산 단위 코드.
- 기존 회귀 테스트는 해당 유틸리티의 증거로 보존하되, 구 COMPLETE/결과 비저장/응답 형식 테스트는 새 계약에 맞춰 재작성한다. 구 테스트를 만족시키려고 새 기획을 거꾸로 바꾸지 않는다.
